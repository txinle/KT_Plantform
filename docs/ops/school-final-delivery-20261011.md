## 普通保存并离题


| 原链路 | 业务目的和必要依赖 | R7 的处理 |
|---|---|---|
| `flushConfirmed` | 指针写入前确认目标事件；旧实现还等待待发检查点和较早在途上传 | 普通导航冻结本客户端、该会话的实际事件边界和相关检查点，在同次请求持久化；不等待无关上传或未来心跳。正式旧协议和工具所需确认仍保留。 |
| 自动保存 / `saveQueue` | 已发出的指针写入可能改变版本，必须取得其结果后冻结 CAS 版本 | 只等待已进入租约/指针写入的请求；尚未发出的重复保存停止单独传输，其已记录事实进入导航包。没有用提前返回虚构远端保存成功。 |
| 工具写入 | 工具引用真实答案事件及服务端曝光/操作事实 | 工具写入保留自己的确认；导航不依赖未来的工具动作。已发生事件保留原 ID，独立检查点不按相似内容删除。 |
| 租约获取 | 保证合法客户端写入，既有实现已经缓存有效租约 | 前端只读取有效缓存；没有有效租约时在同次服务端操作中合法获取，不额外发起租约 RPC。 |
| 关闭旧题 | 记录实际点击离题及本次检查点 | 本地记录一次 `item_left`，附实际目的题 ID 和原导航令牌；与草稿及边界事实同次提交。不预造下一题进入或反馈曝光。 |
| 租约释放 | 释放本客户端持有的写权限 | 同次事务中校验并释放；取消独立释放 RPC。 |
| 下一题读取与准备 | 授权读取、记录实际进入，以及实际 DOM / 恢复资源就绪 | 继续独立于上一题保存事务。下一题读取失败不会回滚已确认草稿；它仍计入点击至下一题可用时间。 |

R7 在现有草稿 URL 接收有界 `save_and_leave`：最多 100 个事件、100 个检查点、8 MiB 请求。复用事件摄入、检查点、草稿、截止时间和租约服务，在一次 durable 事务中保存并生成不可变导航回执，保持暂存语义，不产生正式提交。CAS 也适用于无答案的导航。回执以 Attempt × 原 token 唯一，检查材料指纹；只有真实 COMMIT 返回后才能确认。

浏览器先将完整令牌与材料存入 IndexedDB，收到完整且匹配的确认后才清理对应本地事实并导航。响应丢失保留相同 token、事件 ID、检查点 ID、版本和材料，刷新后可重放。服务端已存回执在开关关闭后仍可在权限检查通过时返回；材料冲突不能覆盖回执。只有明确证明新事务已回滚的拒绝才解除不确定状态；COMMIT 或提交后处理异常保留未知状态。其他客户端租约不会被夺取。

默认关闭 `SAVE_AND_LEAVE_ENABLED`，仅候选 allowlist 开启。本地验证为后端 78 项针对性检查、56 项采集器检查、436 项前端单元测试、API 类型生成/校验、lint/type/build，以及真实 Chromium 的丢失响应刷新恢复、五类题目/IME/离线轨迹、延迟上传确认。双协议开启的五题浏览器见证有 5 次原子提交，129 个唯一客户端事件均已 ACK、持久化，序号、归属、投影哈希和缺失检查通过。隔离候选中仅普通导航协议开启的三人全卷 3/3 完成，完整持久化核对通过。这些检查证明功能与数据契约，不能代替 180 人下的等待时间验收。

R7 镜像冻结源 SHA-256：`cca72b76cc377af073e7c9c2bb05e21ebeb1118755e942e2d432e70e53a26cca`；前端包 SHA-256：`83e6ff83b7198f7321a41b0c307aac8cc56f65c9fe1f2c520d26c34cf5922451`。已结束的最终完整轮同时开启普通导航和原子提交，详细追踪关闭，保留原有资源、35 秒请求预算、1750 秒内部预算、1800 秒硬预算及 18 秒题目节奏。由于同时启用了原子提交，不将全部改善归因于普通导航单项改动。


## 最终 180 人验收

180 个协议客户端，每人计划 20 题、58 次访问、18 秒绝对题目节奏；另有 3 条真实浏览器流程。两种新协议同时开启，详细追踪关闭。单请求预算 35 秒、内部预算 1750 秒、主负载硬预算 1800 秒。候选核心为 16 worker、学生读 2、教师读 1；资源与连接池未改变。协议客户端不是 180 个真实浏览器。

- 全卷完成 **0/180**；真实浏览器完成 **1/3**。内部截止触发，主负载退出 1。
- 85,223 次请求尝试：HTTP 200 为 49,687，HTTP 201 为 35,178；179 次 TimeoutError、179 次 InternalBudgetExceeded，无收到的主负载 HTTP 4xx/5xx。358 次失败尝试对应 179 个失败请求操作，重试恢复 0；顶层另记录 179 个 RuntimeError 和 1 个 InternalBudgetExceeded。
- 真实浏览器有两次返回失败，分别约 35.023、35.033 秒。对应草稿请求返回 409，具体拒绝码未被冻结探针记录，原因未确定。登录前 `/api/v1/auth/session/` 的 401 单独保留，不能与导航拒绝混为一谈。
- 持久化有 1,800 次逐题正式提交。42,241 个已 ACK 事件、28,974 个已 ACK 检查点的材料核对通过；23 个未 ACK 事件与 58 个未 ACK 检查点也已找到且材料匹配。3,944 份导航回执均存在，但并非全部确认，严格核对失败。
- **已确认事实核对通过，完整数据及流程核对未通过。** 未完成及未确认不能转换成容量通过，也不能直接认定已确认事实丢失。
- 发生器动作落后 P50/P95/P99 为 720.740/1418.276/1434.914 秒，最大 1451.723 秒；峰值 RSS 364,630,016 字节。后续到达节奏已被服务等待拖慢，不是持续维持理想到达率的证明。
- 三个观察器正常退出，保护未触发，绑定文件一致；后台在 300 秒预算内实际 0.892 秒排空。本轮自有候选服务已停止，共享 PostgreSQL 保持原身份并继续运行。

## 单个请求为什么慢


R6 在正式轮结束、后台任务清空后，单独运行一次有界 180 人诊断：内部预算 240 秒、硬预算 300 秒，详细追踪开启，资源配置和 R6 应用镜像不变，原子提交关闭。另有三条浏览器短流程。该轮用于定位请求耗时，不作为容量或完整全卷验收。

同一 request ID / operation ID 关联了 58 个浏览器、Nginx 和应用记录，并以事务中的真实 PostgreSQL backend PID 关联 100 ms 间隔的数据库等待采样。下表是各组的中位数，单位秒；列之间存在包含或重叠关系，不能横向相加。

| 请求 | 样本数 | 浏览器总耗时 | Nginx 进入至应用记录开始 | 应用记录范围 | 新连接建立 | SQL | 显式 COMMIT | 提交后回调 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 检查点 | 20 | 2.877 | 2.660 | 0.249 | 0.044 | 0.152 | 0.00406 | 0.000004 |
| 事件批次 | 12 | 3.330 | 2.652 | 0.717 | 0.054 | 0.547 | 0.01014 | 0.000004 |
| 租约获取 | 3 | 3.591 | 3.400 | 0.176 | 0.065 | 0.070 | 0.00290 | 0.000004 |
| 草稿保存 | 3 | 2.956 | 2.563 | 0.360 | 0.059 | 0.224 | 0.00280 | 0.000004 |
| 租约释放 | 3 | 2.657 | 2.358 | 0.219 | 0.065 | 0.097 | 0.00528 | 0.000003 |
| 研究工具 | 17 | 3.080 | 2.595 | 0.356 | 0.051 | 0.222 | 0.00269 | 0.000003 |

入口前区段占各请求 Nginx 耗时比例的中位数约 89.2%。这一证据把主要等待定位在应用记录范围之前，但该区段还包含请求传输、upstream 分发和框架处理，不能将其全部称为 worker 排队。数据库新连接建立与 SQL 已分别记录；连接指标不是 PgBouncer 后方物理连接的完整等待测量。

SQL 耗时包括执行及等待，自提交 SQL 包含其隐式提交。部分查询确实观察到锁等待；采样不能排除不足 100 ms 的短等待，也不能直接把采样次数换算为精确锁持有时间。显式 COMMIT 的最大观察值约 0.429 秒，不能据此声称所有提交都很快；这组证据亦不足以将整段慢请求归因于 WAL 或磁盘。没有更改 fsync、同步提交、NTP 或存储配置。

## 实现范围

- `deploy/docker-compose.school.yml`、`deploy/nginx/kt-school.conf`、`deploy/docker/pgbouncer-school.ini.template`：六个 HTTP 服务池、按方法和精确路径分类、固定数据库用户及连接预算。答案与必要事件的原子操作仍在 `assessment` 内完成。
- `server/apps/api/`、`server/apps/accounts/`、`client/src/app/`：bootstrap 合并 CSRF 与认证上下文，登录返回轮换后的 CSRF；Redis 原子 TTL 续期，不重建已删除会话，不降低持久化强度。
- `server/apps/assessment/event_batch_services.py`：同一事务内合并物化版本更新，完全重复事件回放不更新未变化的 ingest 序号。
- `client/src/assessment-runtime/`：1.5 秒仅显示收尾进度，30 秒传输上限后保留未知结果的原操作标识与恢复记录；普通及最后一题保持服务端确认边界。
- `server/apps/analytics/`、`server/apps/experiments/publication_jobs.py`、`server/scripts/ops/school_capture_priority.py`：教师端读取物化结果及准备状态，压力期间暂停领取低优先级任务；压力控制采用有有效期的信号文件，不动态修改 worker 或 CPU 配额。
- `server/scripts/load/`、`server/scripts/ops/school_transition_runtime.py`、相关见证验证命令：固定人数、完整操作分母、实际活跃重叠及独立数据库一致性验收。

本候选版本同时包含本会话先前已授权的切题事务衔接、离线资源复用及测量改动。基线比较评估整个候选配置，不能把差异单独归因于拆池。

### 10 人服务器证据与定位边界

- 350 次压力采样中，`assessment`/`capture` 的最大 CPU 限流比为 0，监控的 PgBouncer 等待连接数最大值为 0。前后 `cpu.max` 与 Docker CPU 配置相同，控制器正常退出；未动态调整配额或 worker。
- 主机可用内存最低 10,057,375,744 字节；swap 使用量开始/结束均为 28,397,568 字节，无 OOM。该轮没有显示内存不足，不能据此推断 180 人内存需求。
- 最慢一次提交至下一题为 2.484 秒。收尾请求耗时 1.255 秒，其中两次 PostgreSQL commit 等待合计 0.841 秒；该请求 worker 入口等待约 0.0017 秒。另一次 1.880 秒切题的租约获取 commit 为 0.313 秒，答案提交 commit 为 0.608 秒。这些请求保留了同步持久化确认。
- 369 次数据库采样记录了 10 个 `WalSync` 等待样本、6 个 `WALWrite` 等待样本；未采到有 `blocking_pids` 的行阻塞。瞬时采样不能排除采样间隔内的锁等待，也不能给出精确锁等待时长。
- 本轮 PostgreSQL WAL 计数增加：write 4835、sync 4830，stats reset 未改变。`track_wal_io_timing=off`，因此没有可用于分解底层 WAL 写入与刷盘时间的统计；其时间字段为 0，不能解释为没有 I/O 等待。
- 个别 Redis 会话读取也有延迟：最慢链中一项会话读取约 0.234 秒；其余所列请求的会话读取为毫秒级，`session_save_count=0`，未把普通请求重新变成全量会话保存。

## 部署与回滚边界

本轮不直接发布生产。后续生产切换须在批准的发布窗口执行：保留当前镜像、Compose/Nginx/PgBouncer 配置及业务开关；先停止新写请求入场并排空在途写入，再切换同一候选后端镜像的六服务池和对应路由/连接池，验证健康及关键端点。共用密钥、Redis 会话与业务数据库，不能独立更新某一 HTTP 池。

回滚同样先排空在途写请求，再恢复成套旧路由/池配置。已固定为 transition version 1 的会话及待恢复操作仍需兼容的 API：优先回滚路由和资源配置、关闭新会话的 transition 开关，同时保留支持该协议的候选后端及对应客户端资源，直至现存会话与恢复操作收敛。不能只把后端二进制退回不识别 `next_entry` 的 `e64535f`，而让新客户端继续发送已冻结的请求。

保留已提交答案、回执、事件和持久化队列，不删除数据库、volume 或会话。先前授权的 transition 字段迁移为兼容性新增，不能通过反向迁移删除已提交数据。旧应用镜像的完整回退需另行确认现存协议及离线恢复的兼容条件；本次未执行或认证生产回滚。

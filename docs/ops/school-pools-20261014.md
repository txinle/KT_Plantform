- 350 次压力采样中，`assessment`/`capture` 的最大 CPU 限流比为 0，监控的 PgBouncer 等待连接数最大值为 0。前后 `cpu.max` 与 Docker CPU 配置相同，控制器正常退出；未动态调整配额或 worker。
- 主机可用内存最低 10,057,375,744 字节；swap 使用量开始/结束均为 28,397,568 字节，无 OOM。该轮没有显示内存不足，不能据此推断 180 人内存需求。
- 最慢一次提交至下一题为 2.484 秒。收尾请求耗时 1.255 秒，其中两次 PostgreSQL commit 等待合计 0.841 秒；该请求 worker 入口等待约 0.0017 秒。另一次 1.880 秒切题的租约获取 commit 为 0.313 秒，答案提交 commit 为 0.608 秒。这些请求保留了同步持久化确认。
- 369 次数据库采样记录了 10 个 `WalSync` 等待样本、6 个 `WALWrite` 等待样本；未采到有 `blocking_pids` 的行阻塞。瞬时采样不能排除采样间隔内的锁等待，也不能给出精确锁等待时长。

- 个别 Redis 会话读取也有延迟：最慢链中一项会话读取约 0.234 秒；其余所列请求的会话读取为毫秒级，`session_save_count=0`，未把普通请求重新变成全量会话保存。

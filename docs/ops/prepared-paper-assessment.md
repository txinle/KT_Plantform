## 协议与数据边界

- 学生唯一执行流程为“上一题／下一题、保存草稿、最后提交试卷”。`assessment_flow_version=0` 只描述历史记录，逐题提交/跳过HTTP接口鉴权后统一409；原finish URL只接受整卷持久受理。兼容的未结束capture-v2/transition-v1会话保留原身份、冻结题目、计时和材料，补齐整卷投影并单次记录协议切换审计；冻结协议不兼容则明确要求教师处理，不重建会话。已结束历史不改写。
- 预备会话为 `prepared`，`started_at`、个人截止时间、访问及曝光记录为空。学生任务列表与教师已开始统计不把它当作进行中；研究会话导出排除未开始会话，`sessions.csv` 保留 `assessment_flow_version`，不能直接混合解释两种正式提交语义。
- 信心分配仍由冻结规则决定。行内概率是绑定当前答案 head 的草稿；改答清空当前值，历史事件保留。`0` 是有效值，空值不是零；未答题不生成正式信心回答或虚构弹窗曝光。缺失原因使用 `confidence_skipped/v3`，历史事件版本不重写。
- 单题期限与个人期限继续由服务器判断。单题已关闭时允许在有效会话内回看，拒绝答案写入；返回不会重新计时。
- `submitting` 表示已持久接收并冻结材料；`202` 不表示评分已完成。结果开放仍由原反馈政策控制。
- prepared 不能走旧 resume 激活；已接收提交的会话也不会因新增排期版本被 resume 重新开放。已开始会话的恢复不占用首次激活名额；新流程复用已经冻结的信心分配。

新增迁移为 `0037_prepared_assessment_resources`、`0038_activation_cancellation_fence`、`0039_confidence_draft_missing_reason`。它们增加表、版本字段与状态约束，不删除真实数据或重写历史回答。

## 配置与预算

整卷流程为唯一学生入口，`ASSESSMENT_PREPARED_ENABLED`仅保留读取旧配置的兼容字段，设为0也不启用旧执行流程。启动仍须正确配置准入保护，未配置时明确拒绝启动：

```text
ASSESSMENT_PREPARED_ENABLED=1
ASSESSMENT_ADMISSION_ENABLED=1
ASSESSMENT_ADMISSION_GLOBAL_ENABLED=1
ASSESSMENT_ADMISSION_CAPACITY=<实验 C>
ASSESSMENT_ADMISSION_RATE_PER_SECOND=<实验 R>
```

新流程的全局准入覆盖全部任务，首次开始请求在 Redis 原子取得实际执行名额；容量或速率不足返回 `429 START_BUSY` 与 `Retry-After: 1`，不创建预约或开始个人计时。C 必须小于等于启动 HTTP worker 与启动 DB 连接预算。仓库默认从既有额度划分 startup 2、assessment 6；HTTP 合计仍为 20，普通 DB 连接仍为 23，reserve 仍为 3。后续隔离候选曾实测 4/4 划分，见末节；它不是已经验收的生产配置。后台原 3 个连接划分为 background 2、submission 1。新增服务不能被理解为增加总容量。

新流程只有 `executing` 占用 C，并绑定唯一执行代次；不再创建 queued/admitted 或浏览器状态轮询。首次激活返回 `201`，数据库固定回执重放返回 `200`，同一操作已在执行时返回 `202`；前端保存原启动意图，按相同 client/navigation 身份重试。历史流程保留原协议。执行状态不按普通 TTL 直接回收。数据库固定回执或持久取消栅栏允许后台安全释放；数据库/Redis 不可核验时保留占用。Redis 调用不在数据库事务内执行；客户端连接池按 URL 与进程 PID 复用，fork 后不会借用父进程客户端。

发布及修复产物存于 `MEDIA_ROOT/assessment-papers`，文件完整落盘、校验后才设置就绪状态。生产 Nginx 的 `/assessment-content/` 直接读取该目录，不能代理 Django 内容组包。发布 worker 必须挂载同一 `media_data` volume。备份与恢复须同时保留数据库内容描述及对应静态文件。

## 2026-10-15 首轮服务器隔离试验（预约协议，已被后续整改替代）

## 2026-10-15 最小整改复核（当前候选）

本轮只使用学校服务器隔离环境。最终结论为：**预约与轮询机制已移除，恢复不变量通过；180 人启动和混合保存仍未通过性能验收，不选择上线 C/R。** 以下结果不能用上一节的功能恢复成功替代。

当前入口沿用原 URL：一次开始请求原子取得执行名额后直接激活，首次成功 `201`、固定回执重放 `200`、实际执行中的同一操作 `202`、无容量 `429 START_BUSY / Retry-After: 1`。新流程没有预约名额、任务轮转或 admission/status 轮询。Redis 客户端按进程复用；请求遇到 Redis 响应超时，最多用同一执行代次重放一次同一 Lua 调用，既不重新计入放行速率，也不允许另一个 HTTP 执行者冒领。两次响应都丢失时仍关闭准入并保留未知执行，等待数据库取消栅栏；没有延长 500 ms 单次超时或放宽持久性要求。

其余题目预取、解密和缓存写入移至首题可操作之后；首题本地持久化、写资格与离线准备仍是开放作答的前置条件。`process_runtime`、`offline_prepare` 和本地存储计时继续导出。未新增登录会话存储、服务、依赖或数据库表。

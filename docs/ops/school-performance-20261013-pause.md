## 已实现的修复

1. **完整请求计时与会话候选。** 计时覆盖 SessionMiddleware 响应保存，分别记录会话读取/保存和响应阶段；Redis 会话只在显式隔离配置下启用，沿用 Cookie/CSRF 契约。配置 AOF always、noeviction、固定资源和独立持久卷；故障明确返回 503，不自动回退数据库。
2. **收尾确认传播与恢复。** `closeAttempt()` 向调用方返回真实确认结果，未确认时保留原事件、检查点及恢复标识；显示已提交但收尾待确认的状态，避免将已关闭标志误当服务器确认。重试复用原操作身份。
3. **收尾合并与 ACK 调度。** 新增原子收尾 bundle，将收尾材料与租约释放纳入同一确认边界；ACK 进度保留在 IndexedDB，优先随后续批次发送，在线空闲时按既定调度补发；完成前排空待发材料。
4. **原子提交上下文复用。** 事件、检查点、草稿和提交路径复用已锁 session/attempt 及批量验证上下文，更新必要字段和缓存；保留外层事务、截止时间判定、版本一致性和幂等回执。
5. **验证驱动与审计。** 自然作答协议、真实浏览器和服务端核验同步覆盖信心填写/跳过、轨迹、导航、检查点、回执、答案版本与导出。浏览器驱动增加等待阶段观测，并修复按钮消失时的检测竞争；本地进度传输修复 Windows 文件共享冲突。驱动修复不等于产品性能提升。

## 失败与诊断记录

- Redis 访问上限 1 秒的候选曾发生约 1.002 秒响应阶段会话保存超时及 503。可能出现业务已提交而响应失败的边界已保留；5 秒是访问上限调整，未改变持久化、资源限制或验收目标。
- 一次浏览器启动文件冲突及后续延迟启动造成到达节奏不一致，该轮主动终止，不作为标准性能对照。
- 浏览器在正常切题时可能先看到收尾重试按钮、随后按钮被卸载；检测器等待不存在元素导致假 35 秒超时。已以失败测试定位并限制该次状态检测等待，保留原业务等待预算。
- Windows 上传读取持续更新的进度文件曾造成重命名冲突；本地读取改用共享删除权限，上传使用稳定副本。定向复现验证后重新运行完整 Redis 轮。
- 早期响应复制缺陷与以上所有中断记录均保留在独立证据目录，没有并入完整轮成功样本或删除失败。

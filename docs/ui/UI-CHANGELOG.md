# UI change log

更新日期：2026-08-04
实施依据：`E:\ATOP\KT Research UI Optimization Plan.md`

## Design read

KT Research 是面向教师、研究管理员和学生的教育研究数据产品，而非营销站点。界面应可信、克制、清晰、稳定且可访问：教师端保留较高信息密度，学生端优先降低答题过程中的认知负担。

设计强度：视觉 4/10、动效 2/10、密度 6/10、可访问性 10/10、研究语义保真 10/10。

## 主要改动

- 将 Bootstrap 5.3.8 CSS/JavaScript 本地化，消除断网时布局与交互整体失效的 P0 风险。
- 重构全局导航、页面标题区、状态标签、表格、表单、空状态和错误摘要；增加跳转链接、活动导航、ARIA 状态和移动端折叠菜单。
- 用可访问的站内确认对话框和行内错误替代答题页的原生 `alert()` / `confirm()`；补充草稿保存、提交、超时和题目状态的文本反馈。
- 重构教师端题库、导入、实验、结果、班级和学生页面，使操作顺序、发布风险、导出隐私语义和空状态更明确。
- 重构学生端仪表板、答题页和完成页；扩大选项点击目标，增加当前题状态、移动端题号导航与保存状态播报。
- 登录页仅在 `DEBUG=True` 时展示演示账号；补充 403/404/500 页面和轻量 Django Admin 品牌样式。
- 新增项目级设计技能 `.agents/skills/kt-research-ui/`、项目约束 `AGENTS.md`、UI 审计与设计系统文档。

## 教师工作区层级修订

- 修复桌面端教师模块导航被 Bootstrap 折叠规则隐藏的问题。
- 为全部教师页面增加可点击的层级目录，并移除重复的返回链接。
- 教师端和学生端统一显示“姓名 · 登录账号”；移动端保持可见，长文本安全截断。
- 教师主页按内容准备、参与者管理和实验采集分组，补充班级与学生管理入口。

## 研究语义与接口保持

- 未改变 URL、表单字段名、服务端评分、随机顺序、发布快照、答题锁定、计时或导出逻辑。
- 保留答题页原有 DOM 钩子和 Fetch 请求契约；仅增强可访问状态、错误呈现和确认流程。
- 区分匿名 KT 导出、导航事件导出和含身份导出，未把匿名性或因果解释扩大到后端实际保证之外。

## 尚未闭合的风险

1. 需要在真实 Chrome/Edge 中补做 1440×900 与 390×844 的视觉回归。
2. 需要使用独立测试库完成完整导入—发布—作答—超时—导出流程，避免演示数据掩盖边界条件。
3. UI 改造没有提升研究设计本身的因果识别能力；界面中的“匿名”“结果”“正确率”等表述仍必须服从数据字典和研究方案。

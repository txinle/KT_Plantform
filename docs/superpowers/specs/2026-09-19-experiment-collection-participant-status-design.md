# 单实验采集状态与学生明细设计

## 1. 背景与问题

课程内实验详情的“采集状态”页当前只展示班级级汇总，并且前端只显示“未开始、进行中、已完成”。后端进度接口已经返回 `expired`（已超时）和 `invalidated`（已作废），因此现有页面会出现可见状态之和小于参与者总数的情况。

班级中心“学生表现”页汇总一个学生在多个实验中的表现，不适合直接扩展为单一的完整会话状态。经确认，本次不修改该跨实验页面，而是在已经限定单个实验的“采集状态”页补齐状态并增加学生级筛选明细。

## 2. 目标

1. 班级进度表完整展示单实验的五种互斥状态：未开始、进行中、正常完成、已超时、已作废。
2. 在同一页面提供学生级明细，可按班级、姓名或学号、状态筛选。
3. 以发布时参与者快照为统计全集，使没有会话的学生仍能作为“未开始”出现。
4. 保证每个班级的五种状态数量之和等于该班任务的参与者总数。
5. 保持现有作答、提交、计时、超时处理、批改和高级数据行为不变。

## 3. 非目标

- 不修改班级中心“学生表现”的跨实验状态口径。
- 不把简答题“待批改”混入作答会话状态。
- 不新增或修改数据库字段、迁移或会话状态。
- 不改变参与者快照、任务排期、截止时间或终态判定。
- 不在浏览器端加载全部参与者后再筛选。

## 4. 页面设计

### 4.1 班级任务进度

“采集状态”页顶部保留现有班级汇总表，列调整为：

`班级 | 状态 | 参与者 | 未开始 | 进行中 | 正常完成 | 已超时 | 已作废`

数值继续来自服务端。前端不得通过已显示列自行推导任何状态。每个班级应满足：

`参与者 = 未开始 + 进行中 + 正常完成 + 已超时 + 已作废`

### 4.2 学生状态明细

在班级汇总表下方新增“学生状态明细”区域。

筛选项：

- 班级：全部班级或当前实验已发布的任一班级；
- 搜索学生：匹配姓名或学号；
- 状态：全部、未开始、进行中、正常完成、已超时、已作废；
- 操作：应用筛选、清除筛选。

明细列：

`学生 | 班级 | 状态 | 开始时间 | 结束时间 | 提交题数`

没有会话的学生显示“未开始”，开始时间、结束时间和提交题数显示为 `—`、`—`、`0`。其余状态直接显示会话事实。默认排序为班级年级、班级名称、学号、参与者快照主键，保证分页稳定。

页面固定每页 25 条。筛选条件和页码写入 URL 查询参数；查询参数同时包含 `tab=collection`，刷新、前进或后退后仍停留在采集状态页。

桌面端使用表格，移动端使用现有移动卡片模式；两种布局显示相同事实。

## 5. 状态口径

学生状态只针对当前实验和对应班级任务，不做跨实验聚合：

| API 值 | 中文显示 | 判定依据 |
|---|---|---|
| `not_started` | 未开始 | 参与者快照存在，但没有对应任务会话 |
| `in_progress` | 进行中 | 会话状态为 `in_progress` |
| `completed` | 正常完成 | 会话状态为 `completed` |
| `expired` | 已超时 | 会话状态为 `expired` |
| `invalidated` | 已作废 | 会话状态为 `invalidated` |

五种状态在一个参与者快照上互斥。现有唯一约束保证同一班级任务和参与者快照至多对应一个会话。

“待批改”仍然统计简答题提交记录，可能与任何终态同时存在，不参与本表状态计算。

## 6. 后端接口

新增只读接口：

`GET /api/v1/teacher/experiments/{experiment_id}/collection-participants/`

查询参数：

- `class_id`：可选，必须属于当前实验的已发布班级任务；
- `status`：可选，仅允许第 5 节列出的五个值；
- `q`：可选，去除首尾空格后匹配姓名或学号；
- `page`：可选，最小值为 1。

无效状态、无效页码或不属于该实验的班级 ID 返回 `400`，不静默退回“全部”。实验不存在或当前用户无管理权限时沿用现有严格的 `404` 权限边界。

响应结构：

- `items`：当前页学生状态行；
- `page`：页码、每页数量、总条数、总页数和当前范围；
- `filters`：服务端确认后的筛选值；
- `class_choices`：该实验已发布班级的 ID 和显示名称；
- `status_choices`：五种状态的值和中文标签。

## 7. 数据查询与性能

查询以 `ExperimentVersionParticipantSnapshot` 为全集，并限定 `class_task__experiment_id` 为当前实验。通过 `class_task`、`class_group` 和 `student` 的关联一次性取得班级与学生信息，再按 `participant_snapshot` 和 `class_task` 关联 `ExperimentSession`。

状态计算发生在服务端查询/投影层：没有关联会话即为 `not_started`，否则使用会话原始状态。搜索、班级筛选、状态筛选、计数和分页均在服务端完成。实现必须避免逐行查询；一页请求不得产生随行数增长的 N+1 查询。

学生明细接口只在用户进入“采集状态”标签时调用。实验详情首次加载不额外请求学生分页数据。

## 8. 前端数据流

1. 实验详情继续加载定义、发布任务和班级进度。
2. 用户进入“采集状态”时，将 `tab=collection` 写入路由，并按 URL 中的筛选值请求学生明细。
3. 应用筛选时将页码重置为 1；分页只改变 `page`。
4. 清除筛选时移除 `class_id`、`status`、`q` 和 `page`，保留 `tab=collection`。
5. 请求期间显示局部加载状态；请求失败时保留筛选控件并显示错误，不用旧结果冒充新筛选结果。
6. 无匹配记录时显示“当前筛选条件下没有学生”，并提供清除筛选操作。

## 9. 权限与隐私

接口沿用课程的 `can_manage` 权限检查。响应只包含该教师可管理实验的发布快照参与者，不回退到当前实时班级名册，也不暴露其他实验或未发布班级的数据。

学生姓名和学号属于教师现有授权页面已经可见的信息。本功能不增加导出入口，也不改变数据下载权限。

## 10. 测试与验收

### 10.1 后端

- 五种状态各有一名参与者时，返回值和筛选结果准确；
- 没有会话的参与者被判定为 `not_started`；
- 班级筛选只返回对应任务的参与者；
- 姓名和学号搜索有效；
- 组合筛选和分页稳定，无重复或遗漏；
- 不返回其他实验、其他课程或未获授权的数据；
- 无效 `status`、`class_id`、`page` 返回 `400`；
- 未授权教师严格返回 `404`；
- 查询数量有固定上限，防止 N+1。

### 10.2 前端

- 班级汇总表显示“正常完成、已超时、已作废”；
- 五项之和与参与者总数一致；
- 状态和班级选项来自服务端；
- 应用、清除、分页正确更新 URL 和请求参数；
- 刷新页面仍停留在采集状态及相同筛选条件；
- 未开始学生正确显示空时间和零提交；
- 加载、空结果和错误状态明确；
- 桌面表格和移动卡片显示相同状态事实。

### 10.3 回归边界

运行实验 API 的目标测试、实验详情前端单元测试、OpenAPI 生成一致性检查、TypeScript 类型检查和前端生产构建。无需运行与本功能无关的全仓库审计，也不修改或重建生产数据。

## 11. 发布与回滚

本功能包含后端只读接口与前端展示变更，不包含数据库迁移。发布时需要同时更新 Web 和 Nginx 前端资源。回滚可恢复上一版本 Web/Nginx 镜像；参与者快照和会话数据没有被改变。

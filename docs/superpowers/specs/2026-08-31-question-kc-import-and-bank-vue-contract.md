# Question–KC Mapping v2、课程 KC 字典与题库 Vue 纵切正式契约

日期：2026-08-31

## 1. 权威边界

- 课程 KC 总库是课程内唯一 KC 字典与唯一创建入口。题库、题目编辑、实验、发布、快照和导出只能引用课程总库中的 KC，不得隐式创建节点。
- Django 模型、Service 和 DRF API 是编码、权限、导入校验、题目树、归档、删除、事务和审计的唯一权威；Vue 只呈现权威响应并收集操作。
- 四列题库 KC 对应表是唯一新标准。旧“主知识点/次知识点”和既有三表工作簿只作为 legacy 输入；解析后必须转换为同一个内部 `QuestionKCTree`，不得保留第二套主/次语义或直接写关联表。
- 每题映射为单根、最大三级的有序树。同一 KC 在同题最多出现一次，非根节点恰有一个父节点，禁止环、多父、孤立节点和超过三级。
- 兄弟 `ordinal` 只用于稳定显示、规范化哈希和确定性导出，不表示先修顺序、认知阶段、重要性、权重或任何研究语义。研究分析不得把 ordinal 当作特征。

## 2. KC 身份与名称

- 新建课程 KC 的 `Concept.code` 必须满足 `KC[1-9][0-9]*`，在课程内唯一且创建后不可修改。`KC1`、`KC2`、`KC10` 按数字后缀自然排序。
- 手工新增必须提交正整数“KC 序号”，服务器生成 `KC{序号}`；不得自动使用最大值加一，也不得冲突后自动改号。
- 课程批量 CSV 固定为 `序号,知识点名称`。序号直接生成代码；新节点说明为空、状态为有效。
- 批量导入支持幂等：同代码且同规范化名称为“无变化”；同代码异名、同名异码为“冲突”；说明不参与比较且不得由批量导入覆盖。
- 规范化名称唯一性由同一个 `CourseKCService` 负责，手工新增、重命名和批量导入必须调用同一规范化与冲突检查。数据库继续以 `(course_id, normalized_name)` 和 `(course_id, code)` 唯一约束兜底，应用层错误不得依赖数据库异常才产生。
- 已归档 KC 保留稳定代码和历史名称，不允许加入新映射；同码同名重复导入只显示“无变化/已归档”警告，不自动恢复。

## 3. 四列 Question–KC 导入

标准表头固定为：

```csv
题目序号,一级知识点,二级知识点,三级知识点
1,KC1,KC2；KC5,KC2>KC3；KC2>KC4；KC5>KC6
```

- 一个题目序号在同一文件中只能出现一次，且必须属于当前题库；否则整批预览不可确认。
- 一级必填且只能一个；二级、三级可空；二级用 `；` 分隔；三级每项必须显式写成 `二级KC>三级KC`，禁止按位置推断。
- 同一文件和单元格允许混用 `kc_code` 与名称。结构分隔完成后，每个 token 依次执行：Unicode NFKC/全半角/空格/大小写/常见标点规范化、代码精确、名称精确、受限 Damerau–Levenshtein。
- 规范化名称长度小于 8 时最大编辑距离为 1；大于等于 8 时最大距离为 2。只有唯一最近候选满足阈值才接受；同距多候选或超阈值直接报错。
- KC 名称允许含 `；/;/>/＞`，但这类 KC 在四列表中必须使用 `kc_code`，不提供二次转义语法。
- 三级关系左侧解析后的代码必须存在于本行二级集合。根、二级和三级不能重复；三级节点只能有一个父节点。
- 确认导入后，该行完整替换对应题目当前 KC 树；文件未列出的题目保持不变。整批确认在一个事务中执行，任何题失败则全部回滚。既有发布快照不受影响。

## 4. Preview batch 生命周期

- 课程 KC 导入和题库映射导入共用 `ImportPreviewBatch` 契约。Preview 成功后持久化服务器端规范化 payload、文件 SHA-256、错误/警告摘要、创建时间和随机批次 UUID；客户端只持有不可猜测的 `batch_id`。
- 批次必须绑定导入类型、课程、可选题库、创建用户和当前会话；其他用户、课程、题库或会话不得读取或确认。
- 批次自创建起 30 分钟过期；过期批次、已消费批次、payload 丢失、文件摘要不一致或绑定不匹配均返回 `409 preview_batch_invalid`。
- Confirm 在锁定课程/题库后重新校验代码、名称、题目、归档状态和权限。Preview 后发生并发变化时返回 `409 preview_stale`，不得部分写入。
- 批次只能成功消费一次。成功事务内记录 `consumed_at`；重复确认返回 `409 preview_batch_consumed`。业务校验失败不消费批次，教师可返回修正文件重新生成 Preview。
- 过期与已消费 payload 可由定期清理任务删除，但最小审计元数据和正式导入 AuditLog 保留。

## 5. 审计、快照与导出

- 题库 KC 导入 AuditLog 持久化批次、题目序号、原始 token、规范化 token、匹配方式、最终名称、`kc_code` 和编辑距离。
- QuestionSnapshot v2 冻结完整代码、名称、父代码、深度、ordinal、schema version 和 mapping hash。后续重命名、归档或活动数据重建不得改写冻结快照。
- Q-matrix v2、题目结构长表、参与者 quota 归属、KT 序列和 CD 集合均使用稳定 `kc_code`；列和集合采用 KC 数字后缀自然排序。
- ordinal 只影响稳定展示和导出顺序，不进入 KT/CD 特征，也不得被描述为知识先后关系。

## 6. 零填充数据收紧策略

- 在启用 `KC[1-9][0-9]*` 创建约束前，必须分别盘点活动 `Concept`、题目映射、实验草稿规则与冻结 QuestionSnapshot。
- 当前本地活动演示数据 `KC000001–KC000010` 按 Phase 6 规则清理最小依赖闭包并由 `seed_demo` 重建为 `KC1–KC10`；不编写仅服务可丢弃演示数据的中间兼容迁移。
- 冻结历史快照及历史导出继续原样读取零填充字符串，不做就地改码。新活动对象和新发布只允许新格式。
- 收紧后，模型/Service/API 不再生成零填充代码；legacy 输入引用历史零填充代码时只能命中仍真实存在的活动 KC，不得猜测改写为新代码。

## 7. 题库 Vue 纵切与唯一视觉基准

- `/teacher/courses/{course_id}/banks/` 默认“题库管理”；`?tab=course-kcs` 为“课程 KC 总库”。非法 tab 回退默认项；刷新、前进后退和直接链接必须恢复状态。
- Vue 是正式目标实现。Django 保留路由、权限、CSRF、Service、API 和 feature flag；旧模板只作迁移期 fallback，不同步新视觉，仅接受维持旧功能所需的最小字段兼容。
- 两张已确认的 1448×1086 示例图是题库模块唯一桌面视觉权威。不得自行重新设计、简化、替换文案或依赖组件默认样式漂移。
- 必须逐项复刻页面宽度、左右栏比例、导航、面包屑、标题、页签、卡片、表格、表单、按钮、Badge、颜色、字体、行高、图标和固定 UI 文案。动态名称、数量和时间必须使用真实服务器数据。
- 示例图已有图标优先复用项目同款 SVG；禁止 emoji、字符图标、新第三方图标库及语义相近但视觉不同的替代图标。
- 不得新增示例图不存在的装饰、渐变、阴影、分割线或交互入口，也不得删除示例图已有元素。主、次、危险、禁用操作的视觉权重必须保持一致。
- 1448×1086 截图叠加验收：关键容器位置/尺寸误差不超过 4px，字体、控件和图标尺寸误差不超过 2px，颜色使用从参考图校准的设计令牌。
- 1440×900 只允许增加纵向滚动，不改变桌面骨架和左右栏关系。390×844 可单列重排，但必须保持相同视觉语言和全部业务操作。
- 功能正确但视觉明显偏离参考图视为未完成；不得以现代化、默认组件风格或视觉优化为偏离理由。

## 8. 实施与退出条件

- 按测试先行顺序实施：Service/模型约束 → Preview batch/API → 四列解析与导入 → 审计/导出 → Vue 页签与导入流程 → 视觉校准。
- feature flag 开启时新 Vue 完成从路由、API、权限、CSRF到错误恢复的完整纵切；关闭时旧模板维持原有功能。
- 只有功能、研究语义、后端/前端回归、PostgreSQL 验证和全部视觉视口验收通过后，才能另行删除旧模板主路径。

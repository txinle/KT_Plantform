# 教师过程页语言与班级设置收敛设计

> 日期：2026-08-29
> 适用分支：`feat/class-teaching-analytics-center`
> 状态：已获用户确认，待实施

## 1. 目标与边界

本变更只处理两个教师端界面问题：

1. 将过程回放页中的内部英文状态码、质量码、原因码和 CoverageRun UUID 改为教师可理解的中文结论及说明。
2. 将班级设置统一收敛到“班级中心 → 班级管理”，移除班级列表中重复的“编辑班级”和“编辑名称”控件。

不改变 RecordingCoverage 的计算规则、原始事件、导出字段、数据中心研究界面或学生端可见范围。原始枚举值仍保存在模型和导出中；本变更仅修改教师显示投影。

## 2. 教师过程页语言

### 2.1 设计原则

- 教师页显示教学可解释的结论，不显示内部代码。
- 每个结论同时说明可用范围，避免把记录缺失解释为学生未发生行为。
- 过程完整性和时间可用性分开陈述；二者不能互相替代。
- CoverageRun UUID、原始缺失原因码和事件时间来源枚举不在教师页面暴露，仍保留于研究导出与审计工具。

### 2.2 过程记录状态

| 内部状态 | 教师标题 | 教师说明 |
|---|---|---|
| `complete` | 过程记录完整 | 已记录本题所需的过程边界，可用于过程回顾。 |
| `partial` | 过程记录不完整 | 可确认最终结果，但部分作答步骤未被记录，不能完整还原过程。 |
| `insufficient` | 过程记录不足 | 记录不足，不能分析作答过程。 |
| `invalid` | 记录存在不一致 | 答案快照、提交或评分事实彼此不一致。 |
| `legacy_unknown` | 历史记录无法评估 | 旧记录没有当前采集契约，不能按新标准判断。 |
| `not_applicable` | 不适用 | 当前题目或任务不要求该类过程记录。 |

### 2.3 时间质量

| 内部状态 | 教师标题 | 教师说明 |
|---|---|---|
| `exact_monotonic` | 步骤间隔可可靠比较 | 同一页面内记录的先后顺序和步骤间隔可用于分析。 |
| `synchronized_estimate` | 时间为同步估计 | 可比较绝对时间，但属于校时估计。 |
| `client_wall_unsynchronized` | 时间仅供参考 | 有客户端时间记录，但未完成有效校时，不作精确间隔判断。 |
| `server_only` | 仅有服务器记录时间 | 可确认服务器收到或提交的顺序，不能视为学生实际操作时刻。 |
| `unknown` | 时间质量无法判断 | 不对步骤间隔作解释。 |

若 Coverage 的时间质量为“步骤间隔可可靠比较”，而单条过程步骤只能显示服务器接收时间，则页面须同时说明“页面显示的时刻为服务器接收时间；步骤间隔仍按同页客户端单调时钟比较”。不得将服务器接收时间表述为学生发生时间。

### 2.4 缺失原因与时间线

常见原因映射如下；未知原因使用“存在未分类的记录缺口”，不回退到英文代码。

| 原因码 | 教师显示 |
|---|---|
| `missing_final_snapshot` | 未保存最终答案快照 |
| `missing_item_left` | 未记录离开题目 |
| `missing_item_rendered` | 未记录题目呈现 |
| `missing_response_state` | 未记录答案状态变化 |
| `response_chain_break` | 答案变化记录不连续 |
| `sequence_gap` | 过程记录序号存在缺口 |
| `tail_gap` / `tail_unknown` | 页面结束前仍有未确认记录 |
| `checkpoint_missing` | 未收到记录检查点 |
| `time_sync_unavailable` | 未完成有效时间同步 |
| `cross_instance_order_uncertain` | 跨页面先后顺序无法精确确定 |

时间线的来源标签改为“同步估计时间”或“服务器接收时间”。同一页面可比较的间隔改为“与上一步的间隔可可靠比较”，不显示 `exact_monotonic` 或 `server_received_at`。

## 3. 班级设置收敛

### 3.1 信息架构

班级列表的单行操作只保留：

- 进入班级中心；
- 删除班级（仅符合既有删除条件时）。

“编辑班级”和“编辑名称”从列表移除。

“班级中心 → 班级管理”新增或保留统一的“班级设置”表单，字段为班级名称、年级、启用/停用状态，并保留停用影响说明。

### 3.2 路由与兼容

- 旧 `class_edit` GET 地址重定向到班级中心的 `section=manage`，保留旧书签可达性。
- 删除独立的 `class_rename` POST 入口；名称修改只经统一 `class_update` 表单。
- `class_update` 继续执行现有 CSRF、课程写入权限、乐观并发 state token、重复名称校验和审计日志。
- 成功保存后返回班级中心的 `section=manage`；校验错误在同一班级管理页回显。

## 4. 验收与回归

1. 过程回放页不出现 `partial`、`exact_monotonic`、`server_received_at`、CoverageRun UUID 或原始缺失原因码。
2. 不完整记录仍给出中文原因和“缺失记录不代表学生未操作”的边界说明。
3. 所有时间质量状态都有中文标题和用途说明。
4. 班级列表不出现“编辑班级”或“编辑名称”。
5. 班级中心的班级管理页能修改名称、年级、启停状态；成功、校验失败和并发冲突均留在或返回该页。
6. 原 `class_edit` 地址可安全到达班级管理页；独立改名地址不再作为应用接口。
7. 既有权限、CSRF、归档课程只读、审计日志、删除规则和响应式布局回归通过。

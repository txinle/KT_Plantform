# KT Data Lab 平台 UI 更新设计规范

日期：2026-08-30

## 1. 目标与边界

本次工作是现有平台的视觉重设计，不是产品功能重构。目标是让 Django 服务端页面、Vue 渐进式页面和学生作答运行时共享同一套视觉语言，并达到用户提供参考图的完成度。

必须保持不变：

- 现有 URL、路由名称和登录后跳转。
- Django 作为权限、任务状态、截止时间、评分、Coverage、随机化和反馈可见性的唯一权威。
- 表单字段名称、字段顺序、提交方式、CSRF、Fetch 契约和 DOM 钩子。
- A+ 发布的 PreviewRun、发布原子性和任务中心化语义。
- 现有按钮的业务语义、危险操作确认和无障碍标签。
- 现有 Django 与 Vue 的渐进迁移边界。

允许改变：

- 视觉层级、字体、颜色、间距、圆角、边框和阴影。
- 页面壳、导航、面包屑和课程上下文的视觉组合。
- 在不改变字段顺序和提交契约的前提下调整布局容器。
- 仅用于悬停、按下、焦点和状态切换反馈的低强度动效。

## 2. 设计判断

这是面向高校教师、研究人员和学生的数据密集型企业产品。采用轻量、可信、克制的 SaaS 视觉语言，参考 Fluent 2 的信息层级和无障碍原则，但不引入 Fluent 组件依赖，也不把产品改造成 Microsoft 风格。

设计参数：

- `DESIGN_VARIANCE: 4`
- `MOTION_INTENSITY: 3`
- `VISUAL_DENSITY: 6`
- 主题：固定浅色主题
- 重设计模式：视觉重构，信息架构与内容保留

固定浅色主题是有意选择。该平台属于数据密集型教学研究工具，用户给出的六张参考图也均为浅色工作界面。本次不扩大范围增加深色模式，但语义令牌不得阻碍未来扩展。

## 3. 视觉系统

### 3.1 品牌与配色

- 品牌深蓝：用于 KT 标志、品牌文字和关键数字。
- 单一操作色：电蓝，仅用于当前导航、主要按钮、链接、焦点和信息提示。
- 页面背景：统一冷灰，避免当前页面之间偏蓝灰、纯白和 Bootstrap 灰混用。
- 表面：白色。
- 状态色：绿色、琥珀色和红色只表达真实的成功、待处理和危险状态。
- 禁止霓虹光效、玻璃拟态、彩色渐变和装饰性状态点。

建议核心色值：

- `--kt-brand-900: #0c3266`
- `--kt-action-600: #145bea`
- `--kt-action-700: #0f49c6`
- `--kt-page: #f6f8fb`
- `--kt-surface: #ffffff`
- `--kt-ink: #111827`
- `--kt-muted: #667085`
- `--kt-border: #dfe5ee`
- `--kt-success: #229246`
- `--kt-warning: #b56a00`
- `--kt-danger: #c93b3b`

### 3.2 字体

不增加网络字体依赖。使用本机中文字体优先的系统字体栈：

`"Segoe UI", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`

桌面字号：

- 页面标题：30px，字重 700。
- 区块标题：18px，字重 650 至 700。
- 主导航：15px，字重 650。
- 正文：14px 至 15px。
- 表格和辅助信息：13px。
- 最小可见正文不得低于 12px。
- 数字使用 tabular numerals，避免指标跳动。

### 3.3 间距与形状

- 基础间距单位：4px。
- 页面水平留白：桌面 40px 至 56px，移动端 16px。
- 主内容最大宽度：1440px。
- 卡片间距：16px 至 20px。
- 卡片内边距：20px 至 24px。
- 卡片圆角：12px。
- 控件圆角：8px。
- 状态徽标：全圆角。
- 阴影仅用于真正抬升的表面，统一使用深蓝染色的低强度阴影。

### 3.4 动效

- 仅实现 120ms 至 180ms 的颜色、边框、阴影、透明度和 1px 位移反馈。
- 按钮按下使用轻微下移或缩放，表达点击反馈。
- 抽屉、对话框和折叠区域保留状态过渡。
- 不增加页面进入动画、滚动动画、循环动画或视差。
- 所有动效在 `prefers-reduced-motion: reduce` 下关闭。

## 4. 页面架构

### 4.1 全局页面壳

教师端桌面导航采用单层白色顶栏：

- 左侧：KT 方形标志和 `KT Data Lab` 品牌文字。
- 中部：保持现有标签和 URL 的主导航。
- 右侧：通知占位不作为新功能实现；仅呈现现有账户身份和退出入口。
- 当前导航使用电蓝文字与底部 3px 指示线。
- 顶栏高度控制在 64px 至 72px，并始终保持单行。

课程名称、课程代码和学期从主导航移入页面上下文区域或紧邻面包屑的位置，不与主导航争夺横向空间。

学生端沿用相同品牌壳，但只展示已有学生导航，不增加教师入口。

移动端保留现有折叠导航逻辑，只更新视觉。不得改变按钮目标、ARIA 属性和 Bootstrap/Vue 的展开契约。

### 4.2 页面头部

页面头部统一为：

- 面包屑。
- 标题与真实状态徽标。
- 一行说明文字。
- 右侧页面级操作，空间不足时移至下一行。
- 存在局部页签时，页签位于标题之后并形成明确的内容边界。

不增加装饰性英文 eyebrow，不改变已有页面名称和业务文案。

### 4.3 内容组件

共享组件视觉契约：

- `Button`：主要、次要、危险和文本操作四种层级。
- `Card/Surface`：普通表面和抬升表面两种层级。
- `DataTable`：低对比表头、单一行分隔、清晰 hover，不把每一行做成独立卡片。
- `StatusBadge`：仅展示真实业务状态。
- `Alert`：信息、成功、警告、危险四态，图标与文字同时表达含义。
- `FormField`：标签在输入框上方，帮助信息和错误信息在输入框下方。
- `LocalTabs`：文字页签加底部指示线。
- `EmptyState`：图标、标题、说明和单一主操作。
- `Drawer/Dialog`：保持现有焦点管理和关闭行为，只改视觉。
- `Metric`：数字层级优先，不使用装饰性进度轨道。

图标优先复用现有 `kt-sprite.svg` 与 Vue `Icon` 组件，避免混入第二套图标风格或新增大型依赖。

## 5. 双栈实现策略

### 5.1 共享主题令牌

新增平台级主题文件 `static/css/kt-theme.css`，作为颜色、字体、间距、圆角、阴影、动效和层级令牌的来源。

- Django `base.html` 显式加载该文件，再加载 `app.css`。
- Vue shell 显式加载该文件，再加载 Vite 构建产物。
- Vue `tokens.css` 只保留 Vue 组件需要的语义别名，值引用平台级 `--kt-*` 令牌。
- Django `app.css` 不再定义一套相互冲突的颜色值。

这使 Django 与 Vue 在运行时使用同一来源，同时不引入新的构建耦合。

### 5.2 Django 页面

通过 `base.html`、共享组件模板和 `static/css/app.css` 完成大部分更新。页面模板只在现有通用类不足以实现参考布局时做局部结构调整。

不得修改：

- 表单 `name`、`id` 和提交顺序。
- `data-*` 行为钩子。
- CSRF 表单。
- 现有 Fetch 和 Bootstrap 行为目标。

### 5.3 Vue 页面

通过 `frontend/src/design-system` 和各 feature CSS 完成更新：

- 扩展 `AppHeader` 的展示结构，但导航链接继续由布局组件提供。
- 保持 Vue 组件 props、emits、API 调用和路由逻辑不变。
- 页面级 Vue 模板仅增加视觉分组所需的非业务容器。
- 不增加 Pinia 状态，不修改 API 客户端和生成类型。

### 5.4 作答运行时

作答页采用更聚焦的页面壳，但继承同一字体、颜色、控件和状态令牌。必须保留：

- 题目导航。
- 草稿保存与离线恢复提示。
- 时间同步和过程采集。
- 跳过、提交和完成流程。
- 所有既有 DOM 与 Fetch 契约。

## 6. 状态与数据流

本次工作不新增数据流。所有加载、空状态、错误状态、权限拒绝和业务成功状态继续由现有 Django context 或 Vue API 响应驱动。

视觉层只做以下映射：

- 服务端或 API 状态值映射到现有状态徽标与提示层级。
- 页面加载映射到与最终布局一致的骨架或既有加载文案。
- 空数据映射到单一明确的下一步操作。
- 可恢复错误使用页内提示。
- 瞬时成功使用现有消息或提示机制。
- 权限和截止时间判断不得在 CSS 或 Vue 展示逻辑中重新推断。

## 7. 响应式与无障碍

- 1440×900 为桌面视觉验收基准。
- 1024px 以上主导航必须保持单行。
- 768px 以下多列内容改为单列，表格使用现有移动卡片或横向滚动策略。
- 操作控件最小高度 40px，关键触控目标尽量达到 44px。
- 正文、按钮、输入框、占位符和状态文字达到 WCAG AA 对比度。
- 保留跳转链接、语义标题、ARIA、键盘导航和 `focus-visible`。
- 不使用仅靠颜色表达的状态。
- 页面不得出现横向溢出、按钮文字换行或控件截断。

## 8. 分阶段覆盖范围

### 阶段 1：基础与页面壳

- 平台级主题令牌。
- Django 与 Vue 顶栏、主导航、课程上下文、面包屑和页面头部。
- 字体、页面宽度、背景和基础响应式规则。

### 阶段 2：共享组件

- 按钮、输入、选择器、文本域、卡片、表格、页签、状态徽标、提示、空状态、抽屉和分页器。
- 同步 Django Bootstrap 覆盖层与 Vue 设计系统组件。

### 阶段 3：教师端功能区

- 课程与设置。
- 题库与 KC。
- 班级中心与学生分析。
- 实验详情、编辑、A+ 发布向导和结果。
- 数据中心、导出、质量与高级工具。

### 阶段 4：学生端与作答运行时

- 课程与实验任务。
- 我的学习、实验结果和单题记录。
- 作答、保存、提交和完成页面。

### 阶段 5：视觉回归

- 重新生成与功能目录对应的桌面截图批次。
- 对教师端、学生端、空状态、成功状态、警告状态和错误状态进行人工视觉检查。
- 修复溢出、错位、重复层级和旧样式残留。

## 9. 验证策略

实现时先运行最窄检查，再进入阶段级验证。

前端：

- 设计系统和受影响 feature 的 Vitest。
- `npm run lint`
- `npm run typecheck`
- `npm run test:unit`
- `npm run api:check`
- `npm run build`
- 相关 Playwright 教师端和学生端流程。

Django：

- UI 契约测试。
- 受影响页面的路由、权限和表单提交测试。
- A+ 发布、学生任务和作答运行时的现有关键测试。
- `collectstatic --dry-run` 或等价静态资源验证。

视觉：

- 1440×900 桌面视口。
- 至少一个窄屏视口。
- 自动检查横向溢出。
- 对主要页面进行截图对比与人工检查。
- 检查按钮对比度、焦点状态、错误状态和 reduced-motion。

## 10. 完成标准

- Django 与 Vue 页面呈现同一品牌、字体、颜色、间距和组件规则。
- 用户提供参考图中的视觉层级在教师端核心流程中得到一致体现。
- 现有功能、权限、路由、表单和 API 契约不变。
- 关键前端与后端测试通过。
- 主要桌面页面无横向溢出、文字截断或按钮换行。
- 新截图批次覆盖原功能目录，并可直接用于后续 UI 复核。

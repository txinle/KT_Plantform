# 教师工作区导航与主页结构优化设计

日期：2026-08-04  
状态：用户已确认设计方向，等待书面规格复核  
范围：教师工作区导航、教师主页主要工作区、全局登录身份信息

## 1. 问题定义

当前教师端二级导航在桌面端受到 Bootstrap `.collapse:not(.show)` 规则影响而被隐藏。结果不是单纯的视觉弱化，而是教师无法识别题库、KC、班级、学生和实验之间的工作区层级。

与此同时，页面缺少连续的目录路径；右上角显示“姓名 / 角色”，不能识别实际登录账号；教师主页“主要工作”也遗漏班级与学生管理入口。这三项问题共同削弱了采集前准备流程的可理解性。

## 2. 设计目标

1. 教师在任一工作区页面都能识别当前模块、当前页面和可返回的上级目录。
2. 教师主页按真实采集流程覆盖内容准备、参与者管理和实验采集。
3. 教师端与学生端统一显示姓名和登录账号，不再用角色名称替代账号。
4. 不改变 URL、权限、数据库结构、表单字段、实验发布或研究数据逻辑。

## 3. 选定方案

采用“顶部模块导航 + 页面面包屑目录”。不采用左侧树形导航，因为它会持续占用题库表格和实验配置页面宽度；不采用单一浏览器返回按钮，因为历史栈不能稳定表达产品层级。

顶部教师模块导航保持六个一级入口：

- 概览
- 题库
- KC 库
- 班级
- 学生
- 实验

当前模块使用文字、下边框和 `aria-current="page"` 三重状态表达。桌面端导航必须保持可见；移动端继续使用折叠菜单。

## 4. 层级目录

在教师端主内容顶部增加语义化面包屑，使用 `<nav aria-label="层级目录">`、有序列表和 `aria-current="page"`。所有上级目录均为真实 URL，不使用 `javascript:history.back()`。

目录规则：

- 概览：`教师工作台`
- 题库列表：`教师工作台 / 题库`
- 题库详情：`教师工作台 / 题库 / {题库名称}`
- 导入与编辑：`教师工作台 / 题库 / {题库名称} / {当前操作或题号}`
- KC：`教师工作台 / KC 库`
- 班级：`教师工作台 / 班级`
- 学生：`教师工作台 / 学生`
- 实验列表：`教师工作台 / 实验`
- 实验创建：`教师工作台 / 实验 / 新建实验`
- 实验详情：`教师工作台 / 实验 / {实验名称}`
- 实验编辑或结果：`教师工作台 / 实验 / {实验名称} / {当前页面}`

桌面端面包屑单行显示；窄屏允许水平滚动，不能压缩成无法辨认的多行字符。现有页面中的重复“返回……”链接在面包屑已完整覆盖相同路径时移除，避免两个返回机制表达不同层级。

## 5. 登录身份信息

教师端和学生端统一为：`{姓名} · {登录账号}`。

示例：

- 教师：`演示教师 · teacher`
- 学生：`学生1 · S001`

账号来自 `user.username`，姓名来自 `user.shown_name`。如果姓名最终回退为账号，则只显示一次账号，避免 `S001 · S001`。身份文本保持只读，不引入个人资料编辑功能。

## 6. 教师主页主要工作区

将原有四个平铺入口改为三个流程组，每组提供两个明确入口：

1. 内容准备
   - 管理题库：创建、复制、导入和编辑题目。
   - 管理 KC：检查知识点及题目关联。
2. 参与者管理
   - 管理班级：维护学年、班级和可用状态。
   - 管理学生：创建学生账号、分班和重置密码。
3. 实验采集
   - 配置实验：设置题库、顺序、反馈、时间和学生分配。
   - 查看采集结果：进入已发布实验的会话和导出页面。

桌面端采用三列流程组，平板端两列，移动端单列。每个入口保持完整点击区域和可见焦点，不新增图标库或前端依赖。

## 7. 实现边界

- 在 `templates/base.html` 提供教师端面包屑插槽和统一身份文本。
- 各教师模板显式声明自己的目录层级，避免根据 URL 字符串推断层级。
- 在 `static/css/app.css` 修复桌面导航的 CSS 特异性，并增加面包屑、身份信息和三组工作流布局样式。
- 在 `templates/teacher/dashboard.html` 重构主要工作区。
- 不新增视图、路由、模型、迁移或第三方包。

## 8. 验收与测试

先增加失败测试，再实现：

1. 教师登录后的响应包含 `演示教师` 与 `teacher`，不再显示“演示教师 / 教师”。
2. 学生登录后的响应包含 `学生1` 与 `S001`，身份格式与教师端一致。
3. 教师主页包含班级和学生管理的真实 URL。
4. 教师主页与教师子页面包含可访问的层级目录和当前页状态。
5. CSS 契约确认桌面端对 `.teacher-nav-collapse` 的覆盖具有足够特异性，移动端折叠规则继续生效。
6. 完整 Django 测试、JavaScript 语法检查、模板加载、关键路由冒烟和 `git diff --check` 全部通过。

视觉验收至少检查 1440×900 与 390×844。若应用内浏览器仍阻止 localhost 导航，必须把该项记录为外部工具限制，不能用单元测试替代视觉结论。

## 9. 非目标

- 不增加教师个人资料编辑或账号修改功能。
- 不改变班级、学生或实验的数据模型。
- 不把教师端改为侧边栏布局。
- 不修改研究变量定义、匿名导出范围或实验因果解释。

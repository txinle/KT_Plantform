# KT Data Platform Local MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a locally runnable Django MVP for multi-experiment, single-question interaction-data collection with teacher, administrator, and student workflows.

**Architecture:** A Django 5.2 LTS monolith uses server-rendered templates, Bootstrap 5.3, and small fetch-based JavaScript modules. SQLite is the zero-configuration local database; PostgreSQL is enabled through Docker Compose for deployment. Published experiments copy immutable question snapshots, while student navigation, drafts, visits, and submissions are recorded in separate transactional tables.

**Tech Stack:** Python 3.13, Django 5.2 LTS, SQLite/PostgreSQL, Bootstrap 5.3.8, vanilla JavaScript, openpyxl, Gunicorn, Nginx, Docker Compose.

## Global Constraints

- Support administrators, teachers, and students; students log in by student number and password.
- Store class, name, and student number internally, but anonymize research exports by default.
- Support single-choice, multiple-choice, numeric, and short-answer questions with A-F options.
- Import questions from Excel/CSV using only sequence, question, options A-F, and answer.
- Import KC mappings from question sequence, primary KC, and secondary KCs; auto-create missing KCs.
- Support fixed, random, and stratified-random ordering; first MVP stratification uses primary KC and difficulty in [0, 1].
- Student UI is single-question with free navigation among unsubmitted questions, server draft autosave, per-question submit-and-lock, and resume support.
- Record first open, last open, visit count, submission time, assigned order, first-open order, and submission order.
- Unanswered, skipped, and timed-out states are not automatically labeled incorrect.
- Published experiments bind immutable question and KC snapshots.
- Local launch must work with SQLite without Docker; Docker deployment uses PostgreSQL and Nginx.

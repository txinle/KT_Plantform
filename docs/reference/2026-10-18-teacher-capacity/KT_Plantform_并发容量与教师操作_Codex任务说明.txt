下面的文字可独立复制为新的实现任务。它描述待做的工作；本次审计没有修改仓库、执行应用测试、发起登录或生产负载，也没有执行删除。

请在 KT_Plantform 仓库中完成登录容量、教师预览与实验删除的最小修复。审计基线为 main 提交 4dd346dcb736755ddbcf4539854a349f2a60289b。开始前核对当前分支和工作区；如果 main 已变化，先逐项检查相关行为是否仍存在，保留用户已有改动，不要回退或覆盖。先交付分 PR 计划、证据和测试设计，再按任务明确允许的本地或隔离测试范围实施。

目标与不可改变的语义

目标是让约 180 名学生集中进场时的登录与首屏请求有可解释的预算，让教师预览和搜索减少重复或不必要工作，并修复实验删除中的关系完整性和错误反馈问题。180 人表示用户数量；请分别建模 60 秒、30 秒、10 秒进入，极端同点突发另列，不能直接写成 180 RPS。

必须保留认证强度、用户隔离、权限范围、真实数据新鲜度、删除确认和并发阻断规则。不能降低密码哈希成本换取性能；不能缓存共享的认证结果、用户作答或跨教师权限的数据；不能以延长所有 TTL 掩盖失效问题；不能通过吞异常、假成功、关闭外键或绕过事务解决删除失败。

学生切题、保存与交卷另有独立任务书。本任务只处理与共享资源竞争和删除引用完整性直接相关的依赖。不要顺手重构作答状态机、导航幂等、交卷快照或无关 UI。保留现有行为已正确的限流重试、防抖、取消和状态轮询上限。

需要实现的具体批次

1. 删除正确性先行。research_deletion.py 的 _raw_remove/_purge_sessions/_purge_experiment_relations 使用手工原始删除，遗漏 PreparedSessionArtifact、PreparedAttemptProjection、PreparedSessionRepair、PreparedActivationCancellation、SessionSubmission、NavigationReceipt、CaptureMutationReceipt、TaskManualClosure 的相关引用。先在真实 PostgreSQL 事务提交中用未 mock prepare_participant 的发布 fixture 固定失败，再逐项定义阻塞、保留或经确认删除。协调活动 worker，避免删除后重建。保留 course、用户、其他班级/实验和共享资源。不要改 PROTECT 为全面 CASCADE 或关闭外键。独立实验 DELETE 走另一旧服务，本批不要混改。

2. 教师状态修复。TeacherDataAdvanced.vue 的 checkStatus 仅 state===ready 时加载，而 schedulePoll 在 ready_count>0 停止，导致部分就绪仍空表；缓存命中分支又在 abort/请求代际递增之前返回，旧慢页可覆盖当前页。为每次完整路由意图建立代际，status 触发重载同样核对最新 query。保留 250ms 防抖、8 项缓存、3 次 status、隐藏停止和同请求合并；首次非空可读版本最多追加一次加载。

3. 后台时间口径。当前 oldest_pending_seconds 是当前投影/来源修订匹配的最新 pending job 中，最早 created_at 到本次查询的年龄，包含排队、执行和重试；并非 ETA 或纯执行时间。显示明确口径及新增 status_checked_at，状态快照与结果缓存分离，不能拿 successful updated_at 代替采样时间。保持有界轮询，拒绝用额外无限查询修正文案。用可控时钟覆盖 running 跨修订、重试、failed/pending 混合、updating、缺 job、最老 job 完成与缓存返回。

4. 登录观测。RequestIdMiddleware 的 ASSESSMENT_PATHS 不含 auth，导致登录 SQL/connection/commit 观测缺口和响应请求 ID 与入站 ID 不一致；已有 WSGI/Gunicorn 登录阶段计时应保留。将观测范围和自动连接重试范围分离，补真实 middleware 路径测试，禁止仅扩大集合意外改重试行为。日志不能含凭证、Cookie、token、账号、学生答案。

5. 教师后端成本。DataScope 的 session_ref 校验与 sessions() 会重复枚举全课程引用，需改为保留全部授权与范围约束的直接查找，批量校验 experiment_ids；q 建议搜索不要带入无关 session_ref/search/student_id。复用同请求 Count/Sum/Max，overview 不加载无用 workspace。以固定 fixture 记录核心 SQL 口径，当前非空 sessions overview 12 个核心 ORM 求值可设建议预算≤8，权限/scope 另计；status 保持2项核心聚合且不读原始明细。

6. 行为游标锁单独 PR。_behavior_page 第一页持全局 advisory lock 做 COUNT/分页/EXISTS，_store_success 共用该锁。缩短稳定 cutoff 临界区，不能直接删锁；隔离 PostgreSQL 并发测试保证新发布时旧 cursor 跨页不重不漏、原版本可读、跨 scope 拒绝，保留来源修订保护。

7. 教师读取与目录缓存。advanced/search 当前 502/503/504 会立即再试一次；改为最多2次、遵守 Retry-After、轻微抖动、取消可中断的限定读策略，status 继续不自动 retry。目录来源 Question/Concept 与研究 result_version 不同，手动刷新目录需实际更新或采用独立修订，不把所有页面改成每次全刷。

8. 登录容量按证据择一。默认 DB session 与已有30秒条件续期、登录 single-flight、仅 LOGIN_BUSY 的30秒有界随机退让均保留。C4是隔离样例：entry15worker/14DB，login12、startup8、heavy总14属于同一entry；不能相加或当线上配置。先测 hash CPU、entry队列、DB连接/commit、session与首屏扇出，再一次改变一个维度。Redis session只在允许的隔离候选下评估，不默认启用，不减少哈希强度。

9. 删除错误与恢复。区分 transport、HTTP和2xx契约解析失败；409应保留具体原因。未知结果暂停重复POST，不能从404推断成功；已有cleanup_id只查询清理。先将on_commit直接文件清理改为真正持久可恢复后台任务；如果数据库删树本身仍超预算，另提operation/202/幂等回执契约，受理与执行都绑定用户确认的不可扩张范围，范围改变重新确认。
